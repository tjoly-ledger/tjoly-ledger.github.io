scope

Attack surface

Everything the library renders comes from outside: images, bitmap fonts, SVG, text in arbitrary UTF-8, input events. A parser bug there is memory corruption on the device.

Every tool below works on one defined attack surface — the LVGL sources actually used, not the whole library. That is 143 C files (102 082 lines) out of 463 upstream. Fuzzing, coverage and static analysis all share that list.

libfuzzer · asan + ubsan

Fuzzing

13 harnesses drive the decoders, the text engine, the software renderer, the layout engines, the input layer and the widget library. They build against the patched tree under AddressSanitizer and UndefinedBehaviorSanitizer.

Corpora and crash files are committed and replayed on every CI run, so all 39 crashes ever found stay in the build as regression tests — an upstream bump cannot quietly reopen one.

Static analysis

Three analysers run in one pass over the same 143 files, clang-tidy with 21 checkers on an explicit allowlist. The step asserts it produced 143 × 3 result files, so a drifting scope fails loudly instead of quietly analysing less.

Suppressions are not inline pragmas. Each is a rule keyed by report hash with a written justification — 26 of them: 10 false positives, 15 intentional, 1 confirmed.

The confirmed one is a real defect, still open. An integer division in the arc widget's rate limiter; closing it means reworking the limiter, not patching the expression. It stays visible rather than suppressed.

The stage is reporting-only — it fails on a tool error, never on a finding count.

It earned its place anyway: 8 of the 50 patches came from it, including an out-of-bounds write through a 4-byte allocation in the grid layout.

pixel-exact

Render regression

Hardening code that draws pixels is only safe if it still draws the same pixels. A stress demo runs 6 rounds on a simulated 480×272 display under ASan, UBSan and LSan.

  • gate
    No sanitizer report.
  • gate
    Heap leak ≤ 100 bytes over the whole run.
  • gate
    32 reference frames, byte for byte. One differing byte fails the build.
  • logged
    Heap fragmentation is printed, with no threshold on it.

References are generated on the unpatched tree. That is what makes the check mean something: 50 patches, not one pixel moved.

pipeline

Every change

Six steps. Only the patch stack aborts the pipeline; the rest report without blocking it, so a failure marks the build red but every stage still produces its result.

  • baseline
    Benchmark baseline on the unpatched tree.
  • gate
    Patch stack — all 50 patches must apply cleanly, or nothing downstream means anything.
  • parallel
    Unit tests — upstream's own suite, 142 case files, on the patched tree.
  • parallel
    Fuzz coverage — replay 30 925 inputs and 39 crashes.
  • parallel
    Static analysis — three analysers, reporting only.
  • parallel
    Stress — sanitizers, leak budget, 32-frame pixel comparison.
  • final
    Benchmark against the baseline from the same job.

The upstream tree is kept verbatim and never edited. Every change is a patch carrying its defect site, trigger condition and reproducer. Upgrading upstream is one replacement plus a rebase of the stack — and the 39 reproducers decide whether that rebase was correct.
